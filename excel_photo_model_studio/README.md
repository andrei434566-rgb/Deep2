# Excel Photo Model Studio

Самостоятельная программа подготовки YOLO11-seg модели по Excel и фотографиям керна. YOLO определяет маски интервалов и классы фаций; отдельный Qwen3-VL LoRA-адаптер пишет черновые краткие описания. Проекты и маски остаются раздельными от Kern Analyzer.

## Готовая Windows-сборка

Исходники версии 0.7.1. Опубликованные сборки размещаются на [странице релизов GitHub](https://github.com/andrei434566-rgb/Deep2/releases). Скачайте все ZIP-части одной версии, распакуйте их в одну папку и запустите `Excel_Photo_Model_Studio.exe`; папка `_internal` должна оставаться рядом.

Портативная Windows-сборка включает CUDA 12.6 runtime и PyTorch; для обучения нужна совместимая NVIDIA GPU и драйвер. Python и отдельно установленный CUDA Toolkit не требуются.

Изменения версии описаны в [примечаниях к 0.7.1](RELEASE_NOTES_0.7.1.md).

## Входной Excel и выходная схема

Во входном Excel нет привязки к номерам колонок. Программа объединяет строки
многоуровневого заголовка и ищет поля по названиям:

- `Интервал отбора керна` — для проверки интервала, прочитанного с фото;
- `Интервал фации по бурению` с подстолбцами `Кровля` и `Подошва` — для масок;
- `Интервал фации по ГИС` — альтернативная система глубин, проверяемая по толщине фации;
- название, код или индекс фации — для класса;
- `Краткое описание` — целевой текст для VLM, обучаемой на подтверждённых вырезках керна;
- ассоциация фаций и обстановка осадконакопления — дополнительные признаки.

Для всего фото используется одна система глубин: по бурению или по ГИС. Явно распознанная подпись задаёт систему; если она неизвестна, сравнивается покрытие в каждой системе, а при равенстве предпочтение отдаётся бурению. Переключение между бурением и ГИС для отдельных соседних фаций запрещено: оно создавало перекрывающиеся маски. Строка с заполненными глубинами ГИС не теряется, если её ячейки по бурению пусты.

OCR отдельно распознаёт подписи глубин у столбиков; числа из разных систем не объединяются в одну пару. Координаты масок рассчитываются от найденных границ физического керна, а не от строки с цифрами. Неоднозначное распознавание остаётся причиной остановки, а не считается доказанным соответствием.

Исходные данные всегда сопоставляются по смыслу заголовков, а не по буквам или
номерам Excel-колонок; перестановка колонок и многоуровневые заголовки не меняют
назначение полей. Это относится и к индексу фации, её названию и краткому
описанию. В создаваемом стандартизированном файле используются собственные
заголовки, в том числе `Индекс фации`, `Название фации` и `Краткое описание`.

## Что делает программа

1. Для большого архива отдельно выбирает папку со всеми Excel и папку со всеми фото, предлагает очередь скважин и открывает их по одной для проверки. После исправления интервалов пользователь подтверждает маски по мере готовности. В накопительный локальный кэш достаточно сохранить хотя бы одну корректную подтверждённую маску; неподтверждённые строки и ошибки на других фото не мешают продолжить позже.
2. Находит многоуровневые заголовки по смыслу. Для интервалов масок явно предпочитает группу `Интервал фации по бурению`, а не соседнюю группу `по ГИС`.
3. Рекурсивно читает фотографии. Ищет скважину и глубину в имени и автоматически распознаёт подписи фотографии и её столбиков встроенным Tesseract OCR. Проверяются диапазон, порядок, физическая длина керна и доступные опорные глубины; один общий интервал отбора керна в подписи не доказывает положение отдельной страницы.
4. Связывает фото и строку Excel при совпадении скважины и пересечении с интервалом фации в выбранной для фото системе глубин. Совпадения только по общему интервалу отбора керна недостаточно для обучения.
5. Находит физические колонки керна на фото, включая короткий или неполный одиночный столбик, исключает линейку глубины, переводит глубину в координаты найденного керна и обводит видимую ширину материала вместо заливки всего прямоугольника столбика.
   Все глубины рассчитываются в целых сантиметрах: `3.03 м` означает ровно `3 м 3 см`. Автоматическая раскладка последовательности по Excel допускается только при согласовании измеренной длины всех страниц и опорных глубин. Длинная фация переносится между столбиками и фото с исходным описанием. Длина последней страницы не сжимается произвольно до остатка интервала.
6. Сразу после сопоставления показывает выбранное фото с цветными масками найденных интервалов на первом экране. Подробная проверка остаётся на второй вкладке. Проверяется каждая подтверждаемая маска: валидный контур, фация и непустое краткое описание. Ошибки по неподтверждённым интервалам и другим фото видны в отчёте, но не блокируют добавление уже проверенного фрагмента.
7. Собирает YOLO segmentation в совместимой с Ultralytics/CVAT структуре и сохраняет рядом `class_metadata.json` с индексом, названием класса и самым частым подтверждённым описанием из Excel.
8. Делит данные на `train` и `val` целыми скважинами, а если это невозможно — целыми фотографиями. Копии одного файла не могут попасть в обе выборки; при невозможности выделить независимый контроль обучение блокируется.
9. Дообучает предобученную модель YOLO11 segmentation (`yolo11s-seg.pt` по умолчанию) строго на CUDA GPU 0. Если CUDA недоступна или выбран checkpoint старого семейства, обучение останавливается: скрытого перехода на CPU и автоматического продолжения старого запуска нет. Во время обучения оставьте приложение открытым; отдельный процесс Python не запускается.
10. Применяет стандартный Ultralytics `best.pt` к фотографиям нового керна и формирует стандартизированный Excel с полями индекса, названия фации и краткого описания. YOLO определяет маску, глубины и класс; отдельный Qwen3-VL LoRA-адаптер генерирует только визуальный текст в уже найденном интервале и не может менять его границы или класс. Сгенерированный текст — черновик, его нужно проверить. Если VLM не загрузилась, используется описание из подтверждённых метаданных. Неполный результат не экспортируется.

Рабочие проекты хранятся в `%LOCALAPPDATA%\ExcelPhotoModelStudio\projects`. Неизменяемый снимок в `%LOCALAPPDATA%\ExcelPhotoModelStudio\confirmed_wells` включает только подтверждённые корректные маски и фото, на которых они находятся. Достаточно подтвердить один интервал; новые подтверждения той же скважины создают новый снимок, а предыдущий сохраняется. Датасет пересобирается из всего каталога. Даже один снимок можно сохранить и экспортировать, но для обучения требуется независимая выборка `val`; до её появления датасет остаётся доступен, а обучение выдаёт понятное требование добавить фото.

## Оптимизация большого архива

- сопоставление, пересчёт, сборка датасета, обучение, YOLO-экспорт и анализ идут в фоновых потоках текущего приложения; повторный запуск `python.exe` исключён, что устраняет сбои Windows Store/Python 3.14 alias, а окно остаётся отзывчивым;
- повторный пересчёт использует кэш разобранного Excel, пока исходный файл и карта столбцов не изменились;
- неизменившиеся предпросмотры масок не создаются повторно;
- предпросмотры больших фотографий уменьшаются до 1800 пикселей по длинной стороне, при этом обучающие маски сохраняют исходные координаты;
- поиск колонок на очень больших фотографиях выполняется на уменьшенной копии и переводится обратно в исходные координаты;
- при сборке датасета фотографии декодируются и обрабатываются последовательно, без хранения всего архива в оперативной памяти; отдельное чтение контрольных сумм защищает от подмены и дублирования файлов.

## Установка и запуск

Требуется Python 3.11 или новее.

```powershell
cd excel_photo_model_studio
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -r requirements-vlm.txt
.\.venv\Scripts\python.exe run.py
```

Для обучения нужна NVIDIA GPU; приложение запускает обучение только на CUDA GPU 0 и не переключается на CPU. По умолчанию используется предобученный checkpoint `yolo11s-seg.pt`; при наличии интернета Ultralytics загрузит его автоматически. Для офлайн-компьютера скачайте официальный `yolo11s-seg.pt` отдельно и укажите его в поле «Локальный .pt». Приложение сначала проверяет выбранный файл и кэш Ultralytics; при неудачной сетевой загрузке показывает это решение, а не оставляет пустую папку запуска.

Перед стартом журнал показывает предупреждения о размере датасета, редких классах и разбиении `train/val`. Маленький или синтетический набор предназначен только для проверки процесса: несколько тестовых фото не могут дать надёжную модель. Для оценки новой скважины желательно иметь отдельные подтверждённые фото нескольких скважин в `val`, а для каждого класса — разнообразные реальные примеры.

## Рабочий процесс

### Массовая загрузка архива

Откройте вкладку `6. Массовый архив` (или кнопку «Много Excel и фото» на первой вкладке), выберите папку с Excel и папку с фото и нажмите «Найти скважины». Подпапки сканируются рекурсивно. Сначала программа сравнивает скважины в именах файлов/папок, а при неоднозначном имени пытается прочитать номер скважины из строк самого Excel. Однозначные пары при включённом флажке автоматически распознаются в фоне: для каждой создаётся отдельный проект, рассчитанные маски и ошибки показываются в очереди. Длинный пакет сохраняет результат после каждой скважины; ошибка одной не прерывает остальные. При спорной паре строка остаётся без фото: укажите папку вручную и нажмите «Распознать все новые». Исходные файлы не изменяются.

Выберите строку и нажмите «Открыть выбранную для проверки» или «Следующая непроверенная». На первой вкладке проверьте/исправьте интервалы фото и пересчитайте маски; при необходимости используйте пошаговую сверку. На второй вкладке проверьте цветные маски и краткие описания, отметьте верные интервалы и нажмите «Сохранить подтверждения» либо «Сохранить и следующая из архива». Очередь и путь к уже созданному проекту сохраняются между запусками в `%LOCALAPPDATA%\ExcelPhotoModelStudio\archive_queue.json`. Подтверждённые фото и маски хранятся отдельно в накопительном кэше; простой флажок в таблице без сохранения в кэш не считается готовой скважиной.

Когда накоплено достаточно независимых фото/скважин, задайте локальные веса YOLO и базовую Qwen3-VL/LoRA на вкладке 3 и нажмите на вкладке 6 «Собрать датасет и обучить YOLO + VLM». Сборка идёт в фоне и автоматически запускает оба этапа только при наличии `train/val` и достаточного числа подтверждённых описаний; иначе датасет сохраняется, а причина остановки показывается в журнале. Можно отдельно нажать «Собрать датасет из подтверждённых» без обучения. Каждая сборка получает новую папку, не перезаписывая предыдущую. Если после сборки подтвердить ещё скважину, старый датасет блокируется для обучения до пересборки: новые маски не должны потеряться молча. Синтетические примеры годятся только для проверки процесса; качественную модель нужно оценивать на независимых реальных скважинах.

### 1. Создать проект сопоставления

В приложении выберите один файл Excel/CSV и папку со всеми фотографиями. Служебный проект создаётся автоматически в `%LOCALAPPDATA%\ExcelPhotoModelStudio\projects`; выбирать конечную папку не нужно. После подтверждения масок фото копируются в отдельный локальный кэш `%LOCALAPPDATA%\ExcelPhotoModelStudio\confirmed_wells`, а исходники не меняются. Появятся:

- `column_mapping.json` — найденные столбцы каждого файла и листа;
- `photo_map.csv` — скважина и интервал каждой фотографии;
- `matches.csv` — доказанные пересечения фото со строками Excel;
- `annotations.csv` — будущие маски, краткое описание и флаг подтверждения;
- `previews/` — цветные наложения;
- `report.json` — сводка и проблемы.

Обработайте первую скважину, исправьте интервалы при необходимости, откройте вкладку «Проверка масок» и подтвердите готовые строки. Нажмите «Сохранить подтверждения»: достаточно одной корректной маски, чтобы она попала в накопительный счётчик. Остальные можно проверить и сохранить позже; затем таким же образом добавляйте другие скважины.

Интервалы фото можно исправить прямо в таблице приложения. Неподтверждённые фото не создают обучающие маски.

### После обновления со старой версии

Откройте исходные Excel и папку фото и выполните «Пересчитать после исправлений» (в CLI — `refresh`). Старый отчёт или прежние подтверждения не доказывают корректность новых масок. Изменение исходников, карты глубин, геометрии или описания требует повторной проверки; при устаревшем состоянии датасет блокируется. После успешного пересчёта создайте новый датасет и обучите новый комплект модели.

### 2. Проверить маски

На вкладке «Проверка масок» просмотрите каждое цветное наложение. Подтверждайте строку только когда верны одновременно:

- скважина;
- глубины фотографии;
- границы интервала на фото;
- индекс и название фации;
- относящийся к этому интервалу текст `Краткое описание`.

### 3. Собрать датасет

Укажите новую папку. Программа создаст:

```text
dataset/
  data.yaml
  dataset_manifest.json
  class_metadata.json
  caption_dataset.jsonl
  crops/train, crops/val
  images/train, images/val
  labels/train, labels/val
```

Для отдельной выгрузки без запуска обучения откройте вкладку «Экспорт YOLO Segmentation». Она собирает все подтверждённые маски из кэша в выбранную новую папку и показывает число фото, масок и классов. Внутри `labels/` находится polygon-разметка YOLO; `data.yaml` можно сразу использовать в Ultralytics. Экспорт дополнительно включает Excel-метаданные классов и подтверждённые краткие описания. Даже один интервал можно сохранить и выгрузить; для обучения нужен независимый `val`, который появится после добавления достаточного числа фото. Исходный кэш не меняется.

### 4. Обучить сегментацию и VLM-описание

Выберите предобученные веса YOLO11-seg, новую папку результата, число эпох и `patience`. Одна кнопка приложения запускает оба этапа последовательно на CUDA GPU 0: YOLO11-seg обучается на подтверждённых полигонах и определяет интервалы/классы фаций; затем LoRA-адаптер Qwen3-VL обучается на тех же вручную подтверждённых вырезках и соответствующих полях «Краткое описание» Excel. В интерфейсе указываются локальная папка базовой Qwen3-VL и исходный `adapter_model.safetensors`; программа автоматически подставляет известное расположение модели на этом компьютере, если оно найдено. Базовые веса размером несколько гигабайт остаются отдельно и в пакет модели не копируются. Для VLM нужно не менее 20 обучающих и 3 независимых проверочных примеров. Если данные, файлы модели или библиотеки VLM отсутствуют, совместное обучение не запускается. Если VLM завершится с ошибкой после YOLO, итоговый пакет не публикуется, а checkpoint YOLO остаётся в папке запусков для восстановления. Описания VLM всегда остаются черновиком для проверки.

Результат:

```text
model_candidate/
  best.pt
  description_vlm/adapter_model.safetensors
  description_vlm/adapter_config.json
  description_training_info.json
  model_contract.json
  class_metadata.json
  data.yaml
  dataset_manifest.json
  training_info.json
```

`best.pt` остаётся обычным checkpoint Ultralytics YOLO11-seg. LoRA в `description_vlm/` генерирует только краткое визуальное описание интервала, уже ограниченного маской YOLO. В контракт модели записан путь к локальным весам базовой Qwen3-VL; при переносе на другой компьютер укажите папку базовой модели в поле анализа. Адаптер-кандидат не считается геологически проверенным: сравните его текст с отложенными скважинами и Excel-описаниями перед использованием.

## Командная строка

```powershell
python run.py create --excel "D:\archive\excel" --photos "D:\archive\photos" --project "D:\work\project_01"
python run.py refresh --project "D:\work\project_01"
python run.py dataset --project "D:\work\project_01" "D:\work\project_02" --output "D:\work\dataset_01"
python run.py train --dataset "D:\work\dataset_01" --output "D:\work\candidate_01" --weights yolo11s-seg.pt --epochs 300 --imgsz 1024 --batch-size 2 --device 0 --vlm-base-model "D:\models\Qwen3-VL-2B-Instruct" --vlm-adapter "D:\models\core_vlm_v3_knowledge_lora\adapter_model.safetensors"
python run.py analyze --model "D:\work\candidate_01\best.pt" --photos "D:\new_core_photos" --output-excel "D:\results\well_description.xlsx" --vlm-base-model "D:\models\Qwen3-VL-2B-Instruct"
```

После ручного изменения `column_mapping.json` или `photo_map.csv` выполните `refresh`. Создание проекта, датасета и результата требует новой папки; `refresh` обновляет служебные файлы существующего проекта. Исходные Excel и фото не изменяются.

## Выход Kern Analyzer

На вкладке «Новый керн → Excel» программа определяет интервалы и фации, формирует стандартизированную таблицу из 23 полей и сохраняет отдельные значения `Индекс фации`, `Название фации` и `Краткое описание`. Исходные Excel-поля обнаруживаются по именам заголовков; порядок и номер исходных колонок значения не имеют. Каталог классов и описания сохранены в `class_metadata.json` рядом с `best.pt`.

YOLO обучается распознавать маски интервалов и классы фаций. LoRA-адаптер Qwen3-VL, если он обучен, генерирует черновое краткое описание по вырезке найденного интервала и подтверждённым метаданным; границы и класс не меняются. Если VLM отсутствует, используется подтверждённый Excel-пример класса.

Наличие `best.pt` означает завершённое обучение, но не гарантирует качество на новой скважине. Оценивайте границы, классы и текст на независимых контрольных фото. Проверки целостности не заменяют такую оценку и не обещают безошибочный OCR на любом оформлении, освещении или качестве исходных снимков.
