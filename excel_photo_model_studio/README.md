# Excel Photo Model Studio

Самостоятельная программа подготовки YOLO11-seg модели по Excel и фотографиям керна. Проекты и маски остаются раздельными от Kern Analyzer.

## Готовая Windows-сборка

Исходники версии 0.6.2. Опубликованные сборки размещаются на [странице релизов GitHub](https://github.com/andrei434566-rgb/Deep2/releases). Распакуйте ZIP целиком и запустите `Excel_Photo_Model_Studio.exe`; папка `_internal` должна оставаться рядом.

Портативная Windows-сборка включает CUDA 12.6 runtime и PyTorch; для обучения нужна совместимая NVIDIA GPU и драйвер. Python и отдельно установленный CUDA Toolkit не требуются.

Изменения версии описаны в [примечаниях к 0.6.2](RELEASE_NOTES_0.6.2.md).

## Входной Excel и выходная схема

Во входном Excel нет привязки к номерам колонок. Программа объединяет строки
многоуровневого заголовка и ищет поля по названиям:

- `Интервал отбора керна` — для проверки интервала, прочитанного с фото;
- `Интервал фации по бурению` с подстолбцами `Кровля` и `Подошва` — для масок;
- `Интервал фации по ГИС` — альтернативная система глубин, проверяемая по толщине фации;
- название, код или индекс фации — для класса;
- `Краткое описание` — целевой текст для отдельной интервальной модели генерации и проверенный запасной вариант;
- ассоциация фаций и обстановка осадконакопления — дополнительные признаки.

Для всего фото используется одна система глубин: по бурению или по ГИС. Явно распознанная подпись задаёт систему; если она неизвестна, сравнивается покрытие в каждой системе, а при равенстве предпочтение отдаётся бурению. Переключение между бурением и ГИС для отдельных соседних фаций запрещено: оно создавало перекрывающиеся маски. Строка с заполненными глубинами ГИС не теряется, если её ячейки по бурению пусты.

OCR отдельно распознаёт подписи глубин у столбиков; числа из разных систем не объединяются в одну пару. Координаты масок рассчитываются от найденных границ физического керна, а не от строки с цифрами. Неоднозначное распознавание остаётся причиной остановки, а не считается доказанным соответствием.

Исходные данные всегда сопоставляются по смыслу заголовков, а не по буквам или
номерам Excel-колонок; перестановка колонок и многоуровневые заголовки не меняют
назначение полей. Это относится и к индексу фации, её названию и краткому
описанию. В создаваемом стандартизированном файле используются собственные
заголовки, в том числе `Индекс фации`, `Название фации` и `Краткое описание`.

## Что делает программа

1. Обрабатывает скважины по одной: после исправления интервалов пользователь проверяет наложения и подтверждает каждую маску. Только полностью подтверждённая скважина добавляется в накопительный локальный кэш.
2. Находит многоуровневые заголовки по смыслу. Для интервалов масок явно предпочитает группу `Интервал фации по бурению`, а не соседнюю группу `по ГИС`.
3. Рекурсивно читает фотографии. Ищет скважину и глубину в имени и автоматически распознаёт подписи фотографии и её столбиков встроенным Tesseract OCR. Проверяются диапазон, порядок, физическая длина керна и доступные опорные глубины; один общий интервал отбора керна в подписи не доказывает положение отдельной страницы.
4. Связывает фото и строку Excel при совпадении скважины и пересечении с интервалом фации в выбранной для фото системе глубин. Совпадения только по общему интервалу отбора керна недостаточно для обучения.
5. Находит физические колонки керна на фото, включая короткий или неполный одиночный столбик, исключает линейку глубины, переводит глубину в координаты найденного керна и обводит видимую ширину материала вместо заливки всего прямоугольника столбика.
   Все глубины рассчитываются в целых сантиметрах: `3.03 м` означает ровно `3 м 3 см`. Автоматическая раскладка последовательности по Excel допускается только при согласовании измеренной длины всех страниц и опорных глубин. Длинная фация переносится между столбиками и фото с исходным описанием. Длина последней страницы не сжимается произвольно до остатка интервала.
6. Сразу после сопоставления показывает выбранное фото с цветными масками найденных интервалов на первом экране. Подробная проверка остаётся на второй вкладке. Маски подтверждаются пользователем после прохождения всех проверок покрытия фото, керна, интервалов фаций и кратких описаний.
   Каждое выбранное фото обязательно: на нём должны быть найдены физический керн и подтверждённый интервал глубины. Проверяется покрытие реально построенными масками, а не только пересечениями числовых интервалов: пропуски, конфликтующие перекрытия и столбики без масок блокируют датасет. Обязательны фация Excel и непустое поле `Краткое описание`; потерянные строки Excel также отражаются в проверке.
7. Собирает YOLO segmentation в совместимой с Ultralytics/CVAT структуре и сохраняет рядом `class_metadata.json` с индексом, названием класса и самым частым подтверждённым описанием из Excel.
8. Делит данные на `train` и `val` целыми скважинами, а если это невозможно — целыми фотографиями. Копии одного файла не могут попасть в обе выборки; при невозможности выделить независимый контроль обучение блокируется.
9. Дообучает предобученную модель YOLO11 segmentation (`yolo11s-seg.pt` по умолчанию) строго на CUDA GPU 0. Если CUDA недоступна или выбран checkpoint старого семейства, обучение останавливается: скрытого перехода на CPU и автоматического продолжения старого запуска нет.
10. Применяет стандартный Ultralytics `best.pt` к фотографиям нового керна и формирует стандартизированный Excel с полями индекса, названия фации и краткого описания. YOLO предсказывает маску и класс, описание берётся из метаданных подтверждённого Excel. Неполный результат не экспортируется.

Рабочие проекты хранятся в `%LOCALAPPDATA%\ExcelPhotoModelStudio\projects`. Отдельный неизменяемый снимок фото и масок добавляется в `%LOCALAPPDATA%\ExcelPhotoModelStudio\confirmed_wells` только после подтверждения всех масок и успешной полной проверки. Следующую скважину можно обработать позже. Датасет пересобирается из всего подтверждённого каталога, поэтому новые скважины добавляются к предыдущим, а неподтверждённый/неполный проект не участвует в обучении. Повторное подтверждение изменённого проекта создаёт новую версию снимка, сохраняя предыдущую.

## Оптимизация большого архива

- сопоставление, пересчёт, сборка датасета, обучение и анализ запускаются отдельными процессами, поэтому окно приложения не блокируется;
- повторный пересчёт использует кэш разобранного Excel, пока исходный файл и карта столбцов не изменились;
- неизменившиеся предпросмотры масок не создаются повторно;
- предпросмотры больших фотографий уменьшаются до 1800 пикселей по длинной стороне, при этом обучающие маски сохраняют исходные координаты;
- поиск колонок на очень больших фотографиях выполняется на уменьшенной копии и переводится обратно в исходные координаты;
- при сборке датасета фотографии декодируются и обрабатываются последовательно, без хранения всего архива в оперативной памяти; отдельное чтение контрольных сумм защищает от подмены и дублирования файлов.

## Установка и запуск

Требуется Python 3.11 или новее.

```powershell
cd excel_photo_model_studio
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Для обучения нужна NVIDIA GPU; приложение запускает обучение только на CUDA GPU 0 и не переключается на CPU. По умолчанию используется предобученный checkpoint `yolo11s-seg.pt`; первый запуск может загрузить его через Ultralytics, если файла ещё нет локально.

## Рабочий процесс

### 1. Создать проект сопоставления

В приложении выберите один файл Excel/CSV и папку со всеми фотографиями. Служебный проект создаётся автоматически в `%LOCALAPPDATA%\ExcelPhotoModelStudio\projects`; выбирать конечную папку не нужно. После подтверждения масок фото копируются в отдельный локальный кэш `%LOCALAPPDATA%\ExcelPhotoModelStudio\confirmed_wells`, а исходники не меняются. Появятся:

- `column_mapping.json` — найденные столбцы каждого файла и листа;
- `photo_map.csv` — скважина и интервал каждой фотографии;
- `matches.csv` — доказанные пересечения фото со строками Excel;
- `annotations.csv` — будущие маски, краткое описание и флаг подтверждения;
- `previews/` — цветные наложения;
- `report.json` — сводка и проблемы.

Обработайте первую скважину, исправьте интервалы при необходимости, откройте вкладку «Проверка масок» и подтвердите каждую строку. После успешной проверки она появится в накопительном счётчике. Затем таким же образом добавляйте остальные скважины.

Интервалы фото можно исправить прямо в таблице приложения. Неподтверждённые фото не создают обучающие маски.

### После обновления со старой версии

Откройте исходные Excel и папку фото и выполните «Пересчитать после исправлений» (в CLI — `refresh`). Старый отчёт или прежние подтверждения не доказывают корректность новых масок. Изменение исходников, карты глубин, геометрии или описания требует повторной проверки; при устаревшем состоянии датасет блокируется. После успешного пересчёта создайте новый датасет и обучите новый комплект модели.

### 2. Проверить маски

На вкладке «Проверка масок» просмотрите каждое цветное наложение. Подтверждайте строку только когда верны одновременно:

- скважина;
- глубины фотографии;
- границы интервала на фото;
- индекс и название фации;
- относящийся к этому интервалу текст `Краткое описание`.

### 3. Собрать датасет

Укажите новую папку. Программа создаст:

```text
dataset/
  data.yaml
  dataset_manifest.json
  class_metadata.json
  caption_dataset.jsonl
  crops/train, crops/val
  images/train, images/val
  labels/train, labels/val
```

### 4. Обучить модели сегментации и описания

Выберите предобученные веса YOLO11-seg, новую папку результата, число эпох и `patience`. YOLO11 учится находить интервалы и классы фаций; после него отдельный компактный символьный декодер обучается писать краткий текст по вырезке подтверждённого интервала, индексу и названию фации, а также толщине. Оба этапа запускаются на CUDA GPU 0. Проверочная часть описаний отделена по тем же скважинам, что и сегментация. Результат:

```text
model_candidate/
  best.pt
  description_best.pt
  description_training_info.json
  model_contract.json
  class_metadata.json
  data.yaml
  dataset_manifest.json
  training_info.json
```

`best.pt` остаётся обычным checkpoint Ultralytics YOLO11-seg. `description_best.pt` — отдельный генератор чернового текста, привязанный к маске конкретного интервала; он не меняет сегментацию. Если не хватает 20 обучающих интервалов и 3 независимых проверочных, текстовая модель не создаётся, а в `description_training_info.json` указывается причина. При анализе такой комплект использует подтверждённый пример описания класса. Нейросетевой текст нужно просмотреть перед геологическим использованием.

## Командная строка

```powershell
python run.py create --excel "D:\archive\excel" --photos "D:\archive\photos" --project "D:\work\project_01"
python run.py refresh --project "D:\work\project_01"
python run.py dataset --project "D:\work\project_01" "D:\work\project_02" --output "D:\work\dataset_01"
python run.py train --dataset "D:\work\dataset_01" --output "D:\work\candidate_01" --weights yolo11s-seg.pt --epochs 300 --imgsz 1024 --batch-size 2 --device 0
python run.py analyze --model "D:\work\candidate_01\best.pt" --photos "D:\new_core_photos" --output-excel "D:\results\well_description.xlsx"
```

После ручного изменения `column_mapping.json` или `photo_map.csv` выполните `refresh`. Создание проекта, датасета и результата требует новой папки; `refresh` обновляет служебные файлы существующего проекта. Исходные Excel и фото не изменяются.

## Выход Kern Analyzer

На вкладке «Новый керн → Excel» программа определяет интервалы и фации, формирует стандартизированную таблицу из 23 полей и сохраняет отдельные значения `Индекс фации`, `Название фации` и `Краткое описание`. Исходные Excel-поля обнаруживаются по именам заголовков; порядок и номер исходных колонок значения не имеют. Каталог классов и описания сохранены в `class_metadata.json` рядом с `best.pt`.

YOLO обучается распознавать сегментацию и класс фации. Соседняя `description_best.pt`, если она была обучена, генерирует черновое краткое описание из вырезки интервала, индекса фации и его толщины; при отсутствии модели или низкой уверенности используется подтверждённый Excel-пример класса.

Наличие `best.pt` означает завершённое обучение, но не гарантирует качество на новой скважине. Оценивайте границы, классы и текст на независимых контрольных фото. Проверки целостности не заменяют такую оценку и не обещают безошибочный OCR на любом оформлении, освещении или качестве исходных снимков.
