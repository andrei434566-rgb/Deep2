# Подготовка модели фаций и перенос на другой компьютер

Заготовка — это фиксированный справочник классов, схема 16 параметров и правила обучения. Это **не обученная модель**. Веса вашей частично обученной модели находятся на другом компьютере: здесь они не проверялись и не дообучались.

## Что зафиксировано

Встроен справочник `Фации_и_литотипы_исправлено_по_новым_фото.xlsx`: 93 исходных варианта описаний, 92 класса для обучения по паре «буквенный код + индекс». Два написания Lms с индексом 13 сохранены как варианты одного класса. Порядок классов одинаков при каждом экспорте, включая пока не представленные в разметке фации.

Модельные названия имеют вид `Dch@47`, `Dch@92`. Разные индексы и регистр букв важны: `DWCH` и `DWCh` не объединяются. Неоднозначный старый код необходимо уточнить в редакторе. Добавление класса в справочник не означает, что модель уже научилась его распознавать.

Литологическое описание собирается из наблюдений по конкретному интервалу. Справочные обстановка, энергия и предполагаемые литотипы — контекст фации, а не подтверждённые факты о данном керне. Неизвестные значения оставляйте пустыми. Цемент, флюидонасыщение и другие признаки не всегда достоверно определимы по фотографии; им нужны дополнительные данные или экспертная проверка.

## Рабочий процесс

1. Импортировать фото с названием скважины и интервалами глубины. Проверить найденные физические столбики керна.
2. Проверить границы слоёв **внутри** столбиков: контакты, пропуски, ошибочно объединённые интервалы. Непрерывная колонка обеспечивает покрытие, но не гарантирует правильную фацию у каждого слоя.
3. Выбрать точную фацию из окончательного справочника; проверить 16 параметров. Только после проверки контура и фации отмечать слой пригодным для обучения. Автоматические предположения не являются эталонной разметкой.
4. Открыть подготовку модели и устранить блокирующие ошибки разметки. Дисбаланс классов сам по себе не запрещает обучение. Для редких классов нужны новые независимые фото: копирование одного фрагмента не добавляет геологических примеров.
5. Экспортировать датасет. Контрольные фото отделены от обучающих; одинаковое исходное фото не может попадать в обе части. При достаточных данных разделение делается по скважинам. На одной фотографии честной контрольной выборки нет.
6. На другом компьютере запустить обучение со своими существующими весами. Полученные веса считать кандидатом, проверить слабые классы, контакты и литологическое описание. Сравнить с исходной моделью, если порядок её классов совместим.

Отложите ещё одну или несколько скважин для окончательного теста и не используйте их ни при обучении, ни при подборе эпох. Контроль `val` выбирает лучшую эпоху и поэтому не заменяет такой тест. До внедрения оценивайте ошибки по каждой фации и границам интервалов, а не только общую среднюю точность.

Экспорт умеренно повышает частоту редких классов повторением примеров только в `train`: не более трёхкратного размера класса и не более двукратного размера всего обучающего набора. Контроль `val` не балансируется. В паспорте отдельно записаны исходные количества и количества после повторения; повторения не считаются новыми независимыми наблюдениями.

## Что переносить

На компьютер с моделью нужны:

- Та же актуальная версия исходников приложения (включая `app`, `prepare_model.py`, `MODEL_GUIDE.md`, `requirements.txt` и обычные файлы запуска).
- Экспортированный датасет целиком: `data.yaml`, `dataset_manifest.json`, `facies_catalog.json`, разметка и изображения в `labels`/`images`, а также файл атрибутов.
- Небольшая папка заготовки из действия экспорта модели, если она выгружена отдельно.
- Ваш доверенный локальный файл `.pt` сегментации. Исходные веса сохраняйте отдельно и не перезаписывайте.

Папку `.venv` и ярлык с абсолютными путями копировать между компьютерами не следует. Создайте окружение заново: Python 3.11+, зависимости `requirements.txt`, подходящие драйвер NVIDIA и CUDA-сборка PyTorch. Конкретную CUDA-сборку выбирают под систему второго компьютера; текущий компьютер этого не проверяет. Программа работает без весов для подготовки и ручной разметки; распознавание требует подключённой модели. Текущий модуль дообучения требует CUDA, обучение на CPU не запускается.

Пример PowerShell из папки приложения, если окружение ещё не создано:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -c "import torch; print('CUDA:', torch.cuda.is_available())"
```

Последняя команда должна показать `True` перед обучением. Если `False`, установка обычных зависимостей оказалась недостаточной: установите совместимую CUDA-сборку PyTorch на втором ПК. Загружайте `.pt` только из доверенного источника: проверка справочника не проверяет безопасность весов.

## Команды без запуска обучения

Пути ниже — примеры; существующие папки экспорта не перезаписываются.

```powershell
.\.venv\Scripts\python.exe prepare_model.py export --output "D:\Facies\blueprint"
.\.venv\Scripts\python.exe prepare_model.py check --blueprint "D:\Facies\blueprint"
.\.venv\Scripts\python.exe prepare_model.py check --dataset "D:\Facies\dataset"
```

`export` и `check` не загружают веса, не скачивают модель и не запускают обучение. Проверка совместимости заготовки проверяет справочник, а не качество распознавания.

## Дообучение на компьютере с моделью

Запускайте только после проверки датасета и CUDA. 50 эпох ниже — пример верхнего предела, а не оптимум для всех скважин. В приложении есть рекомендация эпох; ранняя остановка завершает обучение при отсутствии улучшения контроля.

```powershell
.\.venv\Scripts\python.exe prepare_model.py train --model "D:\Models\my_facies.pt" --dataset "D:\Facies\dataset" --output "D:\Facies\candidate_01" --epochs 50 --patience 12
```

Модель с другим порядком классов может использоваться как источник переносимых весов, но её старую голову классификации нельзя считать уже обученной на новом справочнике. Автоматическое сравнение «до/после» при несовместимых названиях классов пропускается. Отсутствующие в датасете фации остаются необученными/непроверенными — даже если они присутствуют в полном справочнике.

В результате сохраняются `best.pt`, справочник, паспорт датасета и `training_info.json` с метриками и ограничениями проверки. Для подключения кандидата переносите всю его папку, не только `.pt`. Кандидат не становится окончательной моделью автоматически. Если проверка не завершилась или часть классов не была представлена на контроле, это указано в отчёте; считать такие классы проверенными нельзя.

## Чего эта заготовка не доказывает

Без исходных весов, проверенной разметки и независимых скважин нельзя измерить реальную точность, обещать идеальную модель или подобрать точное число эпох. Подготовлен воспроизводимый путь к проверяемой модели; качество определяется следующим циклом «исправление ошибок → новые независимые примеры → обучение → контроль по классам». Отдельная модель наблюдаемых литологических параметров — следующий этап при наличии разметки этих параметров; текущая сегментация фаций сама по себе их не обучает.
