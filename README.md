# Kern Analyzer

Для начала разметки с уже подготовленной выгрузкой CVAT смотрите [README_CVAT_IMPORT.md](README_CVAT_IMPORT.md).

Для автоматической подготовки разметки из послойного описания и фотографий смотрите [README_EXCEL_JPG_IMPORT.md](README_EXCEL_JPG_IMPORT.md).

Готовое описание экспортируется через `Файл → Сохранить послойное описание (Excel/Word/PDF)…`. Excel остаётся редактируемым; Word и PDF используют ту же табличную форму: интервалы керна и фаций, номер слоя, индекс, название, код, краткое описание и примечание.

Минимальная PySide6-основа нового интерфейса Kern Analyzer.

Для запуска одним двойным щелчком используйте единственный ярлык `ЗАПУСТИТЬ Kern_Analyzer.lnk` в корне проекта. Он запускает актуальный `launch_latest.py`: проверяет окружение и встроенный финальный справочник, затем открывает приложение. Для подготовки и разметки файл модели не нужен. Старые BAT/CMD и копии предыдущих сборок в проекте не используются.

## Подготовка модели на другом компьютере

Откройте **«Модель → Подготовка модели и перенос…»**. В одном окне доступны справочник, поиск фаций, количество отмеченных примеров, проверка независимости фото и экспорт. **«Экспорт заготовки»** сохраняет 92 постоянных класса `код@индекс`, описания из Excel, схему 16 параметров и рецепт обучения. Это спецификация, а не обученные веса. **«Экспорт датасета»** переносит только проверенные примеры с паспортом разбиения. Оба действия доступны без модели и GPU.

Для финальной модели неизвестные старые метки нужно явно сопоставить справочнику в карточке слоя. Код с несколькими индексами не сопоставляется автоматически. Чтобы включить слой в обучение, отметьте **«Фация и границы проверены»**. Импорт Excel и простое перемещение вершины сами по себе не подтверждают класс и контур. Ранее импортированные разметки с отметкой проверки рекомендуется пересмотреть.

На рабочем ПК подключите свою модель `.pt` через **«Модель → Выбрать модель сегментации…»**. Локальные старые веса не выбираются автоматически. Подробности переноса, команды проверки и обучения: [MODEL_GUIDE.md](MODEL_GUIDE.md).

## Переносимая версия `.exe`

Для другого компьютера используйте папку со сборкой, а не исходный код. В ней
запускается `Kern_Analyzer.exe` и Python отдельно не нужен. Все созданные проекты
и дообученные модели сохраняются рядом с программой в `Kern Analyzer Data`, поэтому
их не затронет обновление самой программы.

Переносимую сборку можно получить через GitHub: загрузите проект в репозиторий, откройте вкладку **Actions**,
  выберите **Build Windows application** и нажмите **Run workflow**. После
  завершения скачайте артефакт `Kern_Analyzer-Windows`, распакуйте его и запускайте
  `Kern_Analyzer.exe`.

Для локальной технической сборки используется `python -m PyInstaller Kern_Analyzer.spec`; отдельного пользовательского BAT-запускателя в проекте больше нет.

При отправке тега вида `v2.0.0` GitHub также создаёт постоянный Release с
файлом `Kern_Analyzer-Windows.zip`. Его можно скачать по адресу
`https://github.com/andrei434566-rgb/Deep2/releases/latest/download/Kern_Analyzer-Windows.zip`.

Публичная переносимая сборка использует CPU-версию PyTorch, поэтому помещается
в лимит одного файла GitHub и запускается без Python. Она подходит для импорта,
разметки, подготовки датасета и проверки модели на CPU. CUDA-дообучение выполняется
из исходного проекта на компьютере с NVIDIA по инструкции `MODEL_GUIDE.md`.

На другой ПК нужно переносить всю распакованную папку сборки, а не только один
`.exe`: PySide6, YOLO и остальные библиотеки находятся в соседней папке `_internal`.
Свою модель `.pt` выберите в приложении отдельно.

Либо запуск из PowerShell:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run.py
```

Сейчас доступны полноэкранная рабочая область с Miro-сеткой, фотографии в сетке по 20 в строке с ручным перемещением и `Разметка → Детекция и сегментация`.

Через **File → Загрузить фото/PDF…** можно добавить изображения или PDF: каждая страница PDF будет преобразована в отдельное изображение для разметки. Полученные страницы хранятся в `projects/pdf_pages`.

После успешного дообучения готовая модель сохраняется в понятную папку `models/trained/<название проекта>/<дата-время>/`. В ней лежат `best.pt`, `facies_catalog.json`, `data.yaml` и `training_info.json`.

Сегментация использует CUDA при наличии, иначе CPU. Дообучение требует CUDA; экспорт и подготовка доступны без неё. Во время сегментации и дообучения появляется окно с текущим файлом или номером эпохи.

При сохранении проекта исходные фотографии копируются в его папку `images/`. После дообучения сохраняется кандидат и отчёт качества по классам. Он не заменяет выбранную модель и ручную разметку автоматически. Контроль `val` используется для выбора эпохи; для окончательной оценки нужны дополнительные независимые скважины, не участвовавшие в подборе.

Большие поступления через «Загрузить фото/PDF» обрабатываются партиями по 24 файла, а для отображения используются рабочие превью с максимальной стороной 1600 px; это ограничивает расход оперативной памяти. Исходные файлы остаются в проекте.

Для фото с интервалом в имени вида `Р-25_2984,00-2986,95.jpg` границы полигона и глубины слоя синхронизированы: изменение верхней или нижней границы полигона меняет цифры интервала, а изменение цифр интервала вертикально изменяет подсветку полигона. Для Excel-импорта шкала хранится отдельно для каждой колонки керна в фотографии.

При сегментации используется явно выбранная пользователем модель. После обработки всех фото справа от сетки появится общий столбик в порядке загрузки; подсветки фаций показаны и на отдельных фото, и в столбике.

## Отдельный этап столбиков керна

Каждое новое фото теперь всегда проходит два этапа:

1. независимый модуль находит физические столбики керна и отбрасывает фон, линейки и подписи;
2. модель фаций работает только внутри этих границ.

Найденные столбики собираются в одну вертикальную ленту без разделителей. Вся выделенная длина закрывается интервалами. Участок без достаточного прогноза отмечается «Не определена» и требует проверки: геометрического пробела нет, но случайная фация не назначается.

На втором этапе каждый столбик дополнительно делится по устойчивым изменениям цвета, текстуры и слоистости. Каждый полученный интервал подаётся модели фаций отдельным увеличенным фрагментом, поэтому один столбик может содержать несколько разных фаций. Соседние интервалы стыкуются без пустот; одинаковые классы не склеиваются обратно, если между ними обнаружен структурный контакт.

Любой слой можно поднять или опустить на одну позицию: откройте его параметры правой кнопкой на исходном фото или в собранном столбике и используйте **«↑ Слой выше» / «↓ Слой ниже»**. Те же команды доступны по правой кнопке в дереве проекта. Порядок сохраняется вместе с проектом; для привязанных глубин интервалы пересобираются вплотную, без пустых промежутков.

Финальный справочник `Фации_и_литотипы_исправлено_по_новым_фото.xlsx` встроен в приложение: 93 исходных варианта сгруппированы в 92 пары «код + индекс» (у Lms один индекс и два варианта написания). Исходные определения сохранены. Коды различают регистр, например DWCH и DWCh. Справочная характеристика в отчёте отделена от наблюдённых 16 литологических параметров. Визуальные подсказки параметров принимаются человеком в карточке слоя, а не подставляются как факты.

В меню **«Столбики»** можно проверить и поправить границы на фото, выбрать готовую отдельную модель или обучить её. В обучение попадают только фото, где границы были явно подтверждены интерпретатором; минимум — 3 фото. До первого обучения автоматически используется детерминированный детектор.

При выборе другой фациальной модели приложение сразу предлагает переразметить все фото. Эту же операцию можно запустить позже через **«Модель → Переразметить фации…»**. Границы столбиков сохраняются, а текущие фациальные маски, включая ручные правки, заменяются после явного подтверждения.

Дисбаланс частот фаций внутри одной скважины считается естественным. Проверка датасета покажет его как предупреждение, но не будет блокировать дообучение.

Режим **«Макс. эпох → авто»** даёт эвристический ориентир по маскам, фото, скважинам, классам и качеству разметки; число эпох не является гарантией точности. Экспорт всегда разделяет независимые фото, по возможности — скважины; точные копии одного изображения не допускаются в разных частях. Если независимый контроль сформировать нельзя, нужно добавить фотографии, а не разделять вырезки одного фото. Естественный дисбаланс не блокирует обучение; ограниченное повторение редких классов применяется только к обучающей части, контроль остаётся с исходными частотами.

Управление доской:

- перетаскивание фотографии — левой кнопкой мыши;
- перемещение по бесконечной доске — зажатым колёсиком мыши;
- масштаб — колесом мыши;
- удалить выбранное фото — `Delete` или `Backspace`;
- вернуть последнее удалённое фото — `Ctrl+Z`;
- показать все объекты — `Ctrl+0`.
